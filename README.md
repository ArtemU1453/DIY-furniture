# DIY-furniture

[![CI](https://github.com/ArtemU1453/DIY-furniture/actions/workflows/ci.yml/badge.svg)](https://github.com/ArtemU1453/DIY-furniture/actions/workflows/ci.yml)

**Karkas** — конструктор корпусной мебели в браузере: от габаритов шкафа до
раскроя, спецификации и чертежей для цеха.

## ▶ [ОТКРЫТЬ ПРИЛОЖЕНИЕ](https://artemu1453.github.io/DIY-furniture/)

<https://artemu1453.github.io/DIY-furniture/>

Ставить ничего не нужно — приложение открывается по ссылке и работает прямо в
браузере. **Бесплатно**, без регистрации, без рекламы и платных функций.

📖 **[Инструкция пользователя](docs/USER-GUIDE.md)** — от пустого экрана до
чертежей, тринадцать коротких шагов.

## Быстрый старт

1. Откройте приложение по ссылке выше.
2. Нажмите «Новый» на верхней панели: в окне задаются название и габариты
   первого шкафа — ширина, высота, глубина, толщина плиты и схема верха.
   «Создать» — проект готов, детали уже посчитаны.
3. Правьте параметры во вкладке «Шкаф»: полки, перегородки, двери, ящики.
   Кнопка «Новый шкаф» там же добавляет следующее изделие.
4. Материал и кромку назначайте во вкладке «Детали»: выберите деталь —
   свойства откроются справа.
5. Проверьте изделие глазами в разделах «2D-редактор» и «3D».
6. Заберите производственные данные: «Раскрой», «Производство» (спецификация),
   «Цех» (задание в цех) и «Документы» (чертежи).
7. Сохраните проект — «Сохранить» или `Ctrl+S`. Он остаётся в вашем браузере.

Детали, кромка, соединения и присадка считаются сами по модели — вручную
вводить их не нужно.

## Возможности

- проектирование корпусной мебели;
- параметрическое создание шкафов (габариты, полки, перегородки, двери, ящики,
  задняя стенка, цоколь, ножки, схема сборки);
- материалы и библиотека плит;
- кромка: назначение по сторонам, пресеты, расход;
- фурнитура: каталог, размещение, соединения;
- присадка: операции считаются из соединений и фурнитуры;
- 2D-редактор: выбор, размеры, зум и панорама;
- 3D: сцена, материалы, фурнитура, разнос, сечение;
- раскрой листов с картами и остатками;
- спецификация (BOM) по деталям, материалам, кромке и фурнитуре;
- производственный центр: готовность, партии, этикетки, выпуски;
- документы: чертежи деталей, карты раскроя, ведомости; экспорт SVG/PNG/PDF/CSV;
- сохранение проектов в браузере и автосохранение;
- импорт и экспорт проекта одним файлом.

## Данные

Проекты хранятся **локально в вашем браузере** (IndexedDB) — на сервер ничего
не отправляется. Экспорт складывает проект в один файл `*.furniture.json`,
которым можно поделиться или перенести на другой компьютер.

## Development

```bash
npm install
npm run dev        # режим разработки
```

## Build

```bash
npm run build      # production-сборка в dist/
npm run preview    # предпросмотр собранного приложения
```

Сборка статическая: `dist/` — это готовый сайт, который можно отдать любым
веб-сервером или открыть из подкаталога. Пути к ресурсам относительные
(`base: './'` в [`vite.config.ts`](vite.config.ts)), поэтому приложение
одинаково работает и в корне домена, и в подкаталоге вроде `/DIY-furniture/`.

## Deployment

Публикация автоматическая: push в `main` запускает
[`.github/workflows/deploy.yml`](.github/workflows/deploy.yml), который
выполняет `npm ci`, `npm run lint`, `npm test`, `npm run build` и выкладывает
`dist/` на GitHub Pages. Отдельной команды развёртывания нет — используется та
же сборка, что и локально. Запустить публикацию вручную можно кнопкой
**Run workflow** на вкладке Actions. Подробнее — в разделе
[«Порядок выпуска»](#порядок-выпуска).

## Работа с проектом

**Создание.** «Новый» на верхней панели создаёт пустой проект. Изделие
добавляется мастером шкафа: задаются габариты, толщина и схема, остальное
(детали, кромка, фурнитура, присадка) считается по модели.

**Сохранение.** Проект сохраняется локально в браузер (IndexedDB): кнопкой
«Сохранить», сочетанием `Ctrl+S` и автоматически через паузу после изменения.
Кнопка «Открыть» показывает список сохранённых проектов. Ничего не уходит на
сервер — данные остаются на компьютере.

**Экспорт.** «Экспорт» выгружает проект одним файлом `*.furniture.json`. Этот
файл — полный перенос: в нём и модель, и библиотеки материалов, кромки и
фурнитуры.

**Импорт.** «Импорт» открывает такой файл. Файл с повреждённой или чужой
структурой отклоняется с объяснением, а уже открытый проект при этом не
затрагивается.

## Development checks

```bash
npm run typecheck   # проверка типов TypeScript
npm run lint        # ESLint (в т.ч. изоляция слоёв core/engines)
npm run test        # модульные тесты (Vitest)
npm run e2e         # сквозные сценарии в браузере
npm run acceptance  # приёмочный сценарий
npm run perf        # замеры времени разделов и накопления DOM
```

Три последние проверки работают по собранному приложению — сначала
`npm run build`, затем `npm run preview` и адрес предпросмотра аргументом,
например `npm run e2e -- http://localhost:4173/`. Браузер берётся из
переменной `CHROMIUM_PATH`, а если её нет — из установленного Playwright
(`npx playwright-core install --only-shell chromium`).

Перед изменением кода достаточно `npm run lint && npm test`; перед выпуском
прогоняется весь список.

### Что защищает работающую версию

`test/baseline46.test.ts` хранит производственный результат базовой версии:
состав и размеры деталей эталонного проекта, присадку, соединения, кромку и
число листов раскроя. Числа записаны буквально, поэтому любое изменение,
которое сдвинет то, что уходит в цех, уронит тест — и потребует осознанного
решения, а не пройдёт незамеченным.

Эталонный проект в репозитории один — [`test/golden/goldenProject.ts`](test/golden/goldenProject.ts).
Он же используется в `test/production38.test.ts`. Второй эталон заводить не
нужно: расхождение двух эталонов между собой и есть та ошибка, от которой
они защищают.

Если изменение конструкции сделано намеренно, снимите новые значения
запуском эталонного проекта и обновите константы `BASELINE_*` в
`test/baseline46.test.ts` тем же коммитом, что и само изменение.

Регрессия старых проектов — `test/legacy37.test.ts`: все четыре схемы верха и
низа (между боковинами, поверх, под, смешанные) сверяются с геометрией
прежнего движка. Сохранение, открытие, экспорт и импорт — `test/hardening39.test.ts`.

## CI

На каждый push и pull request выполняется
[`.github/workflows/ci.yml`](.github/workflows/ci.yml):

| Job | Что делает |
| --- | --- |
| `checks` | `npm ci` → `npm run lint` → `npm test` → `npm run build` |
| `e2e` | ставит headless-браузер, собирает приложение, поднимает `vite preview` и гоняет `npm run e2e` и `npm run acceptance` по собранной версии |

`e2e` вынесен в отдельный job: браузер ставится долго, и падение сценариев
не должно скрывать причину падения модульных тестов. Снимки экрана упавших
сценариев остаются артефактом запуска.

## Порядок выпуска

```
изменение кода → CI (lint + тесты + сборка + сквозные сценарии)
              → deploy.yml (lint + тесты + сборка) → GitHub Pages
```

Публикация и проверка разведены по разным workflow, но выкладка не полагается
на чужой результат: [`deploy.yml`](.github/workflows/deploy.yml) сам прогоняет
линтер, тесты и сборку до шага публикации. Версия, которая не собирается или
валит тесты, на сайт не попадает — job останавливается на первом же провале.

Тегов и релизов проект не использует: опубликованная версия — это текущий
`main`, а её номер лежит в `version` файла [`package.json`](package.json).

## Слои

```
UI (components, features)      — только представление и ввод
  ↓
Store (app/store, Zustand)     — состояние проекта, выбор, история undo/redo
  ↓
Core (core/*)                  — модель, единицы, геометрия, валидация (чистый TS)
  ↓
Engines (engines/*)            — расчёты за интерфейсами (раскрой, мебель, …)
```

Слои `core/` и `engines/` не зависят от React/Three/store — это гарантируется
правилом ESLint.
